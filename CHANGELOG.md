# Changelog

All notable changes to this project will be documented in this file.

## [Unreleased]

### Added

- Structured keys in NCode.Coordination.Abstractions: a keyspace of a cluster name and typed segments, and keys of text, number and UUID segments with a partition depth, equal by value and matched under a prefix segment by segment ([#6](https://github.com/NCodeGroup/coordination/issues/6)).
- The guarantee vocabulary: consistency, durability, expiry authority, notification delivery and atomicity across partitions, each guarantee defined with the guarantees it implies, and open to guarantees a provider or a consumer defines ([#6](https://github.com/NCodeGroup/coordination/issues/6), [#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1002](docs/decisions/1002-primitives-declare-guarantees-and-the-composition-refuses-a-requirement-no-provider-meets.md), [ADR-1012](docs/decisions/1012-each-primitive-is-an-interface-whose-operations-are-named-with-the-guarantee-dimensions-they-carry.md)).
- Expiry as a validated time to live, measured by the provider from the write, and the conversion of an instant on the caller's clock with an allowance for clock skew ([#6](https://github.com/NCodeGroup/coordination/issues/6), [ADR-1008](docs/decisions/1008-expiry-is-a-duration-on-the-providers-declared-clock-and-an-instant-becomes-one-at-the-caller-with-an-allowance-for-skew.md)).
- Primitive names, a provider's declaration of the guarantees it keeps per primitive or of a primitive it does not support and why, and a feature's requirement of guarantees on a primitive ([#6](https://github.com/NCodeGroup/coordination/issues/6), [ADR-1002](docs/decisions/1002-primitives-declare-guarantees-and-the-composition-refuses-a-requirement-no-provider-meets.md)).
- The contract of every primitive in NCode.Coordination.Abstractions, an interface a provider implements: sessions, membership, leases, semaphores, elections, claims, records with prefix listing, record watches, transactions, occurrences, sets, counters, sequences and notifications ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1012](docs/decisions/1012-each-primitive-is-an-interface-whose-operations-are-named-with-the-guarantee-dimensions-they-carry.md), [ADR-1013](docs/decisions/1013-ownership-is-granted-with-a-fencing-token-and-an-owner-token-and-bound-to-a-session-or-a-time-to-live.md), [ADR-1014](docs/decisions/1014-records-carry-a-keyspace-wide-revision-and-watches-and-transactions-are-written-in-it.md), [ADR-1015](docs/decisions/1015-occurrences-fail-closed-windows-align-to-the-epoch-and-notifications-number-each-topics-messages.md)).
- Every operation named in an open vocabulary with the guarantee dimensions it carries, so a provider's declaration and a feature's requirement refer to the same operations; options extended by name, which a provider honors or refuses ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1012](docs/decisions/1012-each-primitive-is-an-interface-whose-operations-are-named-with-the-guarantee-dimensions-they-carry.md)).
- Ownership proven by a fencing token greater than every earlier grant of the resource, released only by its own owner token, bound to a session or to a time to live, and given back to the session that already holds it ([#7](https://github.com/NCodeGroup/coordination/issues/7), [#10](https://github.com/NCodeGroup/coordination/issues/10), [ADR-1013](docs/decisions/1013-ownership-is-granted-with-a-fencing-token-and-an-owner-token-and-bound-to-a-session-or-a-time-to-live.md)).
- Records with a revision across their keyspace, watches that resync whenever a change may have been missed, and transactions with conditions on revisions or values and writes for either outcome, whose result also says when a write binds a record to a session that has ended ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1014](docs/decisions/1014-records-carry-a-keyspace-wide-revision-and-watches-and-transactions-are-written-in-it.md)).
- Expected outcomes, such as a lost compare-and-swap, returned as results, and failures thrown as a coordination exception with a code and whether the operation may have taken effect ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1011](docs/decisions/1011-an-operation-returns-its-outcome-and-throws-a-coded-failure-that-says-whether-it-may-have-taken-effect.md)).
- Time windows aligned to the Unix epoch for claims and counters, and value types that no default instance can bypass ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1010](docs/decisions/1010-vocabulary-values-are-sealed-record-classes-so-no-default-instance-skips-validation.md), [ADR-1015](docs/decisions/1015-occurrences-fail-closed-windows-align-to-the-epoch-and-notifications-number-each-topics-messages.md)).
- The composition in the NCode.Coordination package: a host registers providers on one builder with `AddCoordination`, each through a configurator of its own that needs only NCode.Coordination.Abstractions, and binds each to every primitive it supports, to some, or to a keyspace and the keyspaces under it; a key goes to the most specific binding, and consumers resolve each primitive's interface from dependency injection ([#8](https://github.com/NCodeGroup/coordination/issues/8), [ADR-1016](docs/decisions/1016-a-host-binds-providers-by-primitive-and-keyspace-and-its-start-fails-on-every-requirement-a-binding-cannot-keep.md)).
- Requirement checking when the host starts: the built-in guarantees, those each provider defines and those the host defines are validated as one set and closed under implication, each provider's declaration and every binding are checked, and the start fails with every problem listed, each unmet requirement naming the feature, the primitive, the provider and the missing guarantees, and once the composition is valid, each provider's startup probe verifies that its server keeps what it declares, before any hosted service starts; a host declared a single node accepts linearizability within one process for a requirement of linearizability ([#8](https://github.com/NCodeGroup/coordination/issues/8), [ADR-1002](docs/decisions/1002-primitives-declare-guarantees-and-the-composition-refuses-a-requirement-no-provider-meets.md), [ADR-1016](docs/decisions/1016-a-host-binds-providers-by-primitive-and-keyspace-and-its-start-fails-on-every-requirement-a-binding-cannot-keep.md)).
- Traces and metrics for every operation through System.Diagnostics: the `ncode.coordination.operation.duration` histogram and a span per operation, tagged with the provider, the primitive, the operation and its outcome, as `docs/metrics.md` lists ([#8](https://github.com/NCodeGroup/coordination/issues/8), [ADR-1016](docs/decisions/1016-a-host-binds-providers-by-primitive-and-keyspace-and-its-start-fails-on-every-requirement-a-binding-cannot-keep.md)).
- The in-process provider in the NCode.Coordination package, added with `AddInProcessProvider` and bound by the name `in-process`, which keeps every primitive in the process's memory: sessions that end at a close or after their time to live and end the memberships, leases, semaphore slots, leaderships and records bound to them; membership with watches; leases, semaphores and elections with fencing and owner tokens; claims; records with prefix listing, watches that replay the last 1,024 changes of a keyspace, and transactions; occurrences, sets, counters and sequences; and notifications numbered per topic. It is safe under concurrent callers, linearizable within the process, volatile and atomic across partitions, expires state on the host's `TimeProvider` as soon as it is due, and tells a watcher or subscriber that falls 1,024 changes behind to resync ([#9](https://github.com/NCodeGroup/coordination/issues/9), [#10](https://github.com/NCodeGroup/coordination/issues/10), [ADR-1008](docs/decisions/1008-expiry-is-a-duration-on-the-providers-declared-clock-and-an-instant-becomes-one-at-the-caller-with-an-allowance-for-skew.md), [ADR-1014](docs/decisions/1014-records-carry-a-keyspace-wide-revision-and-watches-and-transactions-are-written-in-it.md), [ADR-1015](docs/decisions/1015-occurrences-fail-closed-windows-align-to-the-epoch-and-notifications-number-each-topics-messages.md)).
- The conformance kit, the NCode.Coordination.Testing package: a contract suite for every primitive that a provider's xUnit tests derive from, given the provider, a way to advance its clock and a way to drop its connections, covering each operation, its edge cases and expiry, and skipping what the provider declares unsupported; concurrent runs in which three clients race on each primitive while every call and return is recorded, a history checker that searches each key's history, or the one history of the keys a record listing, a counter batch or a transaction spans, for a linearization against the primitive's sequential specification, counts a call whose outcome is unknown as possibly applied and reports the shortest failing prefix, delivery checks of notifications and record watches for at-most-once delivery and gap detection, and fault runs for a paused lease holder and for dropped connections under records, record watches and notifications, each run only for the guarantees the provider declares; the in-process provider passes every suite ([#9](https://github.com/NCodeGroup/coordination/issues/9), [#10](https://github.com/NCodeGroup/coordination/issues/10), [#11](https://github.com/NCodeGroup/coordination/issues/11), [#29](https://github.com/NCodeGroup/coordination/issues/29), [ADR-1006](docs/decisions/1006-every-provider-passes-one-conformance-kit-that-checks-recorded-histories-against-each-guarantee.md), [ADR-1017](docs/decisions/1017-the-conformance-kit-is-a-set-of-xunit-contract-classes-a-providers-tests-derive-from.md), [ADR-1019](docs/decisions/1019-concurrent-runs-record-histories-and-a-checker-searches-each-keys-history-for-a-linearization.md), [ADR-1030](docs/decisions/1030-the-resp-providers-runs-drop-its-own-connections-restart-servers-of-their-own-and-repeat-every-suite-on-a-valkey-cluster.md)).
- The holder's local deadline, `HolderDeadline`, begun on the holder's clock before the request that grants or renews its ownership and passing an allowance for drift before the requested time to live ([#10](https://github.com/NCodeGroup/coordination/issues/10), [ADR-1008](docs/decisions/1008-expiry-is-a-duration-on-the-providers-declared-clock-and-an-instant-becomes-one-at-the-caller-with-an-allowance-for-skew.md), [ADR-1018](docs/decisions/1018-a-holders-local-deadline-starts-before-its-request-and-ends-an-allowance-for-drift-before-the-time-to-live.md)).
- Recipes in the NCode.Coordination package, each resolved from dependency injection, built only on the primitives' contracts so it runs on every provider that keeps what it needs, and required with `RequireRecipe`, which checks its primitives and guarantees when the host starts: locks and read-write locks that wait for a release and carry the fencing token of their grant; barriers that let every party pass once all have arrived; singletons that run a piece of work while their node leads a role and stop it when the leadership ends; partition ownership that gives each partition to one live member by rendezvous hashing, moving it only when membership changes; single-flight, where one node fetches a value while the others wait for it; fixed-window, sliding-window and token-bucket rate limiters that are `System.Threading.RateLimiting` limiters, so ASP.NET Core's rate limiting middleware uses them; and cache invalidation over a notification topic whose resync clears the cache ([#12](https://github.com/NCodeGroup/coordination/issues/12), [ADR-1020](docs/decisions/1020-recipes-use-only-the-primitives-contracts-declare-the-guarantees-they-rely-on-and-wait-on-releases-and-watches.md)).
- Hosting, the NCode.Coordination.Hosting package: `AddCoordinationHosting` takes the node's options from code or from a configuration section bound strictly and validated when the host starts; once the composition's requirements pass, the host opens its session without holding up its start, joins its cluster's membership group with its node id, address and metadata, renews the session on its own clock, treats it as lost at the holder's local deadline, and opens a new one at once; a failed open or join is tried again after a wait that doubles with each failure in a row up to `MaxRetryDelay`, shortened at random by up to half so a cluster's nodes spread their attempts; `IHostSessionService` gives features the current session, a token that ends with it and a wait for the next; once every hosted service has stopped, the host closes the session within its shutdown timeout, releasing every lease and membership entry bound to it at once; `RequireHostSession` fails the start when no binding keeps sessions, and `AddCoordinationCheck` adds a readiness check that reports the host not ready while it holds no session or the provider failed its last call ([#13](https://github.com/NCodeGroup/coordination/issues/13), [ADR-1004](docs/decisions/1004-a-node-holds-a-session-that-binds-its-leases-and-membership-and-every-lease-grant-carries-a-fencing-token.md), [ADR-1018](docs/decisions/1018-a-holders-local-deadline-starts-before-its-request-and-ends-an-allowance-for-drift-before-the-time-to-live.md), [ADR-1021](docs/decisions/1021-a-host-holds-one-session-for-its-lifetime-joins-its-membership-with-it-and-closes-it-as-it-stops.md)).
- The RESP provider, the NCode.Coordination.Resp package, added with `AddRespProvider` and bound by the name `resp`: it reaches Valkey or Garnet through StackExchange.Redis, over a connection it opens and owns from a configuration string or the host's own `IConnectionMultiplexer`, which it never disposes; its Valkey profile needs Valkey 7.2 or later and its Garnet profile Garnet 2.2.13 or later, started with `--lua --lua-transaction-mode`; when the host starts, its probe fails the start when the server is another vendor or an older version, runs no Lua scripts, or refuses them or any command the provider sends to the provider's user; every key carries its keyspace as its cluster hash tag; and every failure says whether the call may have taken effect. It keeps records, persistent, with a time to live or bound to a session, listed under a prefix in pages from an index in the keyspace's slot, each page examining at most its limit plus 64 entries of the index, so a page can be short or empty and still lead to more, and transactions of up to 64 conditions and two branches of up to 64 writes; every record change is one script that takes the keyspace's next revision and publishes it, with the keys it wrote or deleted, on the keyspace's watch channel, and an expired record is absent at once and deleted and announced by the next script on its keyspace. Its record watches, on a key or a prefix, subscribe to that channel, start with a resync at the keyspace's revision and read each written record from the keyspace, delivering it at its write's revision; its notifications publish a payload of up to 4,096 bytes with the topic's next sequence in one script; and each subscription delivers consecutive numbers at most once and resyncs after a gap, a number that goes backwards, a dropped and restored connection, or a check every `CheckInterval`, 5 seconds by default, that finds its channel ahead, and the check of a record or membership watch also deletes and announces the keyspace's expired records, so a lost message, or an expiry in a watched keyspace, is noticed within the interval. It keeps occurrences too, recorded once with a time to live and failing closed; sets whose members each expire on their own, up to 10,000 live members; counters whose time to live starts with the increment that creates them, with batches of up to 16 increments run as one script and counts up to 9,007,199,254,740,991; and sequences that never reset. It keeps the ownership primitives as well: sessions whose every keep-alive renews their whole time to live, ended by a close or by expiry together with the memberships, leases, semaphore slots, leaderships and records bound to them; membership groups read at the keyspace's revision, whose watches list a group again only when the keyspace's event names it; leases, semaphores of up to 1,024 slots and elections, each grant with a fencing token from a counter that never expires and an owner token of 128 random bits, bound to a session or to a time to live; and claims, one `SET` with `NX` and the caller's time to live per name and window. Waits on them, and watches of a role, read the server every 100 milliseconds until their condition holds or the caller cancels. It declares every primitive but notifications linearizable until a failover, every primitive but record watches and notifications volatile, and record watches and notifications at most once with gap detection, measures every time to live on the server's clock, applies a transaction and a counter batch atomically across partitions, and passes their conformance suites against Valkey and Garnet and against a Valkey cluster of three nodes, where every key of a keyspace lies in its slot and its sharded channel on that slot's node, including concurrent runs of every primitive checked for linearizability and declared delivery and runs that drop its connections; across a server restart every failure is unavailable, no call that fails as not applied applies, and every subscription and ### Security

- Every pull request checks the license of every NuGet dependency, transitive ones included, against the permitted licenses ([#6](https://github.com/NCodeGroup/coordination/issues/6), [ADR-1009](docs/decisions/1009-ci-checks-every-dependencys-license-and-no-snippet-scan-runs.md)).
- An occurrence check fails closed: a provider that cannot answer throws, and never reports a key as first seen ([#7](https://github.com/NCodeGroup/coordination/issues/7), [ADR-1011](docs/decisions/1011-an-operation-returns-its-outcome-and-throws-a-coded-failure-that-says-whether-it-may-have-taken-effect.md), [ADR-1015](docs/decisions/1015-occurrences-fail-closed-windows-align-to-the-epoch-and-notifications-number-each-topics-messages.md)).
- Telemetry records no key, key segment, value, payload or exception message, since key names can carry tenant identifiers ([#8](https://github.com/NCodeGroup/coordination/issues/8), [ADR-1016](docs/decisions/1016-a-host-binds-providers-by-primitive-and-keyspace-and-its-start-fails-on-every-requirement-a-binding-cannot-keep.md)).
