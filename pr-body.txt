## Summary

Implement sessions, membership, leases, semaphores, elections, and claims in the RESP provider, completing the ownership primitives for the RESP phase (plan 4 of 6, issue #27).

## What's Implemented

- **Sessions**: Keyspace-scoped with TTL, keep-alive, idempotent close, wait-for-end. All session-bound resources delete atomically when session ends.
- **Membership**: Join/leave groups, read/watch views at revisions. Members are session-bound and expire with the session.
- **Leases**: Exclusive resource ownership with owner and fencing tokens. Bound to session or TTL.
- **Semaphores**: N-slot capacity (1-1,024) with independent fencing tokens per slot. Session or TTL binding.
- **Elections**: Leader election with term (fencing token) and value. Session or TTL binding.
- **Claims**: One holder per named time window, no release, expiry at window end plus skew allowance.

## Architecture

- One Lua script per operation (ADR-1023)
- All primitives stored in one cluster slot per keyspace (ADR-1024)
- Fencing tokens strictly increasing per resource (ADR-1013)
- Session-bound resources delete atomically in one script call
- Idempotent operations: acquiring/leading again with the same session returns existing grant
